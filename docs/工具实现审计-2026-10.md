# 兰台 工具实现审计：半成品与不贴手的地方

> 审计范围：src/main/services/*、src/renderer/src/views/*、src/renderer/src/tools.ts
> 结论口径：只列「实现不彻底 / 交互反直觉 / 与办公场景习惯不符」的实证问题，每条附代码位置。

---

## 一、结论速览

| 分级 | 判定 | 涉及工具 |
|---|---|---|
| P0 硬伤 | 功能名义存在，实际场景用不了或结果不可信 | PDF 压缩、Word 替换（跨 run）、批量提取联系方式 |
| P1 半成品 | 能用但缺关键环节，用户必须绕路/反复试错 | 表格匹配填充、Excel 合并、文件重复查找、二维码识别 |
| P2 习惯不符 | 功能完整，但交互顺序/命名/默认值与办公习惯拧着 | PDF 拆分、页码、水印、批量二维码、时间戳、小工具入口 |

## 二、P0：功能名义存在，实际不可用

### 1. PDF 压缩 —— 「压缩」其实是「整篇转图片」

`PdfView.vue:82-121` + `pdfService.ts:384-398`

- 实现是 pdf.js 逐页渲染成 canvas → JPEG → 用图片重建 PDF。**文字层被彻底抹掉**：压完的 PDF 不能再搜索、不能复制、不能再编辑，也不能再走别的 PDF 工具链（页码/水印都会变成贴在图片上的图层）。
- 页数硬上限 **200 页**（`PdfView.vue:86`），超出直接报错，让用户自己去拆分。而办公场景里 300+ 页的报送材料很常见。
- 全流程在**渲染进程主线程**跑：`for` 循环里 await 每一页，期间界面会明显卡顿，且没有 `isCancelled` 检查——**压缩任务无法中断**（对比 batchPdf 有 `isCancelled`）。
- README「已知限制」里轻描淡写成「文字不可复制」，但这对一个「报送/归档」工具是致命的：压缩后的报送件如果被要求可检索，整条链路白做。

**建议**：至少给「保留文字层」的选项（走 pdf-lib 重编码图片流，或接 ghostscript/qpdf 之类的真实压缩），并把页数上限改为软提示 + 分批。

### 2. Word 批量替换 —— 跨 run 拆词匹配不到（不是"可能"，是办公场景高频）

`replaceService.ts:14-28`

```js
const re = new RegExp(`(<w:t[^>]*>)([\\s\\S]*?)</w:t>`, 'g')
```

- 只在**单个 `<w:t>` 文本节点内**替换。Word 会把一个词按排版拆进多个 `<w:r>`/`<w:t>`（改过字体、加粗、拼音、修订痕迹都会触发拆 run），于是「张三丰」里只换「张三」这种需求会漏掉。
- `replaceService.ts:83-85` 只认 `.docx / .xlsx`，**旧 `.doc` 直接报错**。而单位存量材料大量是 `.doc`——README 说「Office 转 PDF 支持 .doc」，但替换不支持，用户会困惑。
- 更糟的是**静默漏替换**：count 只统计真实命中的，用户看到「替换 0 处」却不知道是没这个词还是被拆开了，没有任何「可能因排版拆开而漏替换」的提示。

**建议**：先在 XML 层面做跨 run 合并（把相邻 `<w:t>` 的文本拼起来匹配再回写），或至少检测到「待查文本被拆散」时给出明确警告。

### 3. 批量提取联系方式 —— 编码与文件名是错的

`extractService.ts:67-100`

- **输出写死 UTF-8**（`extractService.ts:94`），而同一个软件的 CSV→Excel 功能却专门处理 GBK（`excelToolsService.ts:302-304`）。内网台账习惯是 GBK，提取出来的 txt 用单位里的记事本/旧版 Excel 打开会乱码——**自家两个功能编码策略不一致**。
- 无去重时的实现是脏的：`found[kind].add(`${v}#${found[kind].size}`)`（`extractService.ts:80`），用 `#` 拼后缀制造"唯一键"，然后又 `split('#')[0]` 拆回来（`:88`）。如果手机号/邮箱本身含 `#` 会误伤；而且这套逻辑完全可以正当地用一个数组表达。
- 证件号正则 `(?<!\d)\d{17}[\dXx](?!\d)` 会命中**任何 18 位数字串**（订单号、流水号、备案号），没有校验位、出生日期合理性检查，误报率高，用户拿到几百条要先自己筛。

## 三、P1：能用但缺关键环节，用户被迫绕路

### 4. 表格匹配填充（VLOOKUP 替代）

`excelMatchService.ts:64-106`

- **只读第一个工作表**（`:74-75`），却直接 `writeFile` 覆盖整簿——如果主表有多个 sheet，除了第一个其余原样保留（这点还行），但如果用户想匹配的是第 2 个 sheet 就没入口。
- **匹配上的行不保留原表格式**：代码只写 `ws.getRow(outRow).getCell(idx).value`（`:98`），新增列没有沿用主表列宽/样式/条件格式。README 宣称「保留主表格式」，实际只保留了**原来的列**，新列是裸的。
- `matched/unmatched` 计完只返回数字，**不告诉用户哪些行没匹配上**。核对场景最需要的恰恰是"没匹配上的那一批"，用户还得自己回 Excel 用公式找。
- 副表**重复 key 静默取第一条**（`:57`），不提示有重复，匹配结果可能是错的而用户浑然不知。

### 5. Excel 多簿合并

`excelToolsService.ts:78-137`

- 合并模式依赖「每个文件第 1 行是表头」（`:113`）。单位台账里**表头常常在第 2、3 行**（上面有标题/单位名/日期），直接报「没有找到表头」，没有「指定表头行」的选项。
- 表头并集按**列名精确字符串**对齐（`:123-126`），一个空格、全半角差异就变成两列。没有列名模糊匹配/手动映射。
- 同样丢样式丢公式（README 承认），但没有任何提示，用户合并完发现格式全乱。

### 6. 重复文件查找

`inventoryService.ts:102-182`

- **只报告，不能处理**。找出重复组后（UI 列表，`FileKitView.vue`），没有「保留最新 / 保留路径最短 / 一键删除多余」的动作。用户看完列表还得手动去资源管理器删——这正是"不好用"的典型。
- 全量 MD5，大目录（几万文件）无进度、无中止（对比批量任务有取消）。

### 7. 二维码识别（jsQR）

`ToolsView.vue:327-363`

- 只做**单张、单码**识别，且只有 `readFiles` 的第一张（`:338`）。批量识别不存在。
- 失败信息是「没有识别到二维码」，**不区分**是没有码、还是码太糊/倾斜/多码。没有任何**前处理**（灰度、二值化、放大、裁剪），而这些是 jsQR 类库能否成功的关键。README 也承认对模糊/倾斜/多码可能失败——等于把库的短板直接暴露给用户。

## 四、P2：交互与办公习惯拧着

### 8. 「输出位置」能填文件名的设计，与批量工具有冲突

`namePattern.ts` 的 `splitOutputTarget` 让单输出工具能填 `D:\输出\报告.pdf`。但**多输出工具（拆分、批量二维码、提取）只取目录部分**，用户填了文件名会被静默忽略。同一个人在「合并」里填文件名有效、在「拆分」里无效，**行为不一致且无提示**。

### 9. PDF 拆分 / 页码 / 水印的细节

- `splitPdf` 三种模式全是「另存新文件」（`pdfService.ts:92-125`），**没有原地替换原文件的选项**。办公场景「把这份 PDF 删掉第 3 页」更希望覆盖，现在必须另存再手动替换，且原文件名变了（`_删1页`）。
- 页码只有三档位置 + 固定 `9pt` 灰色 + 固定格式 `${n} / ${lastNo}`（`pdfService.ts:145-168`），**字号、颜色、格式、"第X页 共Y页"中文格式都不可调**。页眉页脚反倒能配置（`addHeaderFooter`），两个功能能力不对等。
- 水印文字默认「内部资料」，但把这份**默认值写死在 view**（`PdfView.vue:195`），批量页签里又各写一遍（`:240`）。没有「最近使用的水印」记忆。透明度 `wmOpacity` 默认 20（对应 0.2），但 PDF 里 `Math.max(0.05, ...)` 下限是 0.05，UI 用整数百分比、服务用小数，**两个单位混用**容易出 bug。

### 10. 时间戳小工具

`ToolsView.vue:95-112`

- `tsToDateFn` 判断秒/毫秒的方式是 `raw.replace('.', '').length >= 13 ? n : n * 1000`（`:104`）——**对 11 位秒级和 10 位秒级都乘 1000，但对 13 位以上其实还要考虑负号、科学计数法**，边界脆。
- 秒→日期输入框只读、不支持粘贴带毫秒，也没有「当前时间戳实时走动」。这类小工具用户期望的是**一进去自动就有当前值**，现在要手动点「刷新」。

### 11. 小工具页签塞了 11 个

`ToolsView.vue:13,484-496`

- 单页 11 个 `el-tab` 横排，「JSON / 编解码 / 时间戳 / UUID / 文件哈希 / 二维码 / 提取 / 批量码 / 识别码 / 加拼音 / 文本对比」。**「批量码」和「识别码」缩写到看不懂**，且和「二维码」三者分列，「提取」不写「提取联系方式」。
- 这些工具在命令面板里也有入口，但侧栏只有「常用小工具」一个入口，**深度工具（如批量二维码）很难被找到**。

### 12. 一致性小问题

- 输入校验文案风格不统一：有「请先选择文件」「请先选择 PDF 文件」「请选择文件」（`ToolsView.vue:201` vs `:242`）。
- `runBatchQr` 的 `batchQrOutputs.value = []` 和函数首行写在了同一行（`ToolsView.vue:263`），格式瑕疵，说明这块是"顺手加的"。
- 批量提取结果面板用 `extractResult.counts`，但单文件提取失败时整个任务抛错（`extractService.ts:98`），**一个坏文件搞挂整批**，与其他批量工具的「单文件失败不影响其余」策略不一致。

## 五、横切问题（跨工具）

1. **样式/公式丢失成系统性沉默**：Excel 合并、拆分、匹配全丢样式；PDF 压缩丢文字层；用户每次都要手工检查，产品应该统一在结果面板给出「本次丢失了哪些东西」的说明。
2. **「可撤销」覆盖面窄**：只有重命名/归类有撤销（`undoJournal.ts`），而替换、脱敏、压缩、匹配这些**破坏性更强**的操作都没有撤销或备份提示。
3. **进度/中止不统一**：批量任务（merge/office/replace/zip）有 `isCancelled`，但压缩、拆图、找重复、组织页面这些长任务没有。
4. **单位制混乱**：字体 pt / dpi / 百分比 opacity 三套单位散落各处，UI 与服务层各算各的。

## 六、建议的优先级排序

| 优先级 | 动作 | 理由 |
|---|---|---|
| 1 | 修 Word 跨 run 替换 + 加漏替换告警 | 高频、静默出错、结果不可信 |
| 2 | PDF 压缩改为可选保留文字层 + 去掉 200 页硬限制 | 报送场景刚需 |
| 3 | 批量提取统一 GBK/UTF-8 选择，与其他功能对齐 | 一致性、乱码 |
| 4 | 重复文件查找加「一键处理」 | 从"能用"到"好用"的差距 |
| 5 | 匹配填充输出未命中明细列 | 核对场景核心诉求 |
| 6 | 拆分/页码/水印补齐可配置项与原地覆盖选项 | 贴合办公习惯 |
| 7 | 小工具页签重命名 / 归类 | 可发现性 |
